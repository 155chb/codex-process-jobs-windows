# 原生工具包装实验（2026-09-27）

本文件区分实际验证与尚未完成的接口接入，不代表插件已经可以拦截所有命令。

## 已验证：当前 Windows 桌面原生执行工具中的包装器

在原生工具的默认沙箱内执行 `scripts/auto-run.mjs`，不使用提权选项：

- 短命令在等待预算内返回，保留真实退出码 7 和输出。
- 长命令在 200 ms 等待预算后返回后台任务标识；原生调用返回后，任务继续运行并成功结束。
- 长任务延迟 5 秒后才尝试文件访问，证明测试的是运行期间的权限限制。
- 包装后的实际命令身份为 `CodexSandboxOffline`。
- 允许目录写入成功；允许范围外的新测试文件写入得到 `PermissionError`（errno 13）。
- 工作目录和测试环境变量保持一致。
- 3 项 Node 测试、2 项 Hook 单元测试通过。

命令结束之前返回的后台 receipt 不是成功完成的证据。真实终态和退出码保存在 job.json。

## 尚未验证

- 当前桌面会话的插件 Hook 是否能改写工具参数并实际执行包装器。
- 改写后的命令在自动审批或用户审批流程中是否保持期望行为。
- 网络权限保持、提权调用、命令取消、桌面关闭后的存活。
- 当前 shell 未导出的变量、函数、别名、profile、交互式 stdin 的透明保持。
- 沙箱内后台任务能否直接调用用户身份下的 `codex queue`；不能假设它有该权限。
- 包装后的完成唤醒。此权限实验显式关闭通知。

不通过不等于可以绕开限制。包装器不得转交用户身份下的 Hook/MCP 进程执行原命令。

## Hook canary 的范围和信任

`test/rewrite-probe-hook.py` 只匹配配置中一个完整相等的无害测试命令。
它仅返回改写参数；不执行 payload、不提权、不改变全局配置或 hook trust。
测试不能据此宣布生产版通用命令改写已完成。

`test/hook-probe-cli.py` 是独立的 CLI 兼容性实验，不是当前桌面会话的验证。
其一次性 `--dangerously-bypass-hook-trust` 标志只能在用户明确授权后使用，沙箱保持 workspace-write。
它不安装插件、不修改持久信任。完整测试输出放在忽略的 `.test-state` 内。

插件结构验证工具目前缺少本机 Python 的 PyYAML 依赖，未完成该验证。

## CLI Hook canary 的实际结果

用户批准一次性信任实验后，CLI 正常结束（退出码 0）。Hook 日志和工具输出均确认
执行了改写后的包装器。实验 Agent 得到后台 receipt 后结束本轮，没有轮询或重跑。
后台命令随后成功结束，仍为沙箱用户：允许写入成功，范围外写入被拒绝。
这不是当前桌面会话安装插件的验证；未修改全局 Hook 定义或持久信任。

## 完成通知实验

`completion-relay.mjs` 只读取指定任务状态并向匹配的 owner 提交元数据通知，
不读取或执行原命令，不转移 payload 的权限。通知独立保存在 relay.json，
避免与沙箱 worker 同时覆盖 job.json。持久锁确保不重复发送；不确定的确认不重试。

发现当前桌面会话旧 rollout 文件已停止更新，不能用旧 task_complete 判断当前空闲。
新通知路径使用 Codex queue 模式；旧路径额外拒绝早于任务创建时间的完成证据。
真实桌面唤醒效果仍须由后续新轮次验证，accepted 状态本身不是成功唤醒的证据。
